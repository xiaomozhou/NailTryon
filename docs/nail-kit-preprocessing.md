# 五片美甲素材预处理

## 范围

本次只准备源美甲素材：从十片展示图中选择一组五片，分离甲面蒙版，保留原图颜色、坐标、方向与上下文。没有实现对手部指甲的透视变形、曲面拟合、粘贴或融合算法。现有试戴流程的生成逻辑保持原有实现，仅把参考素材改为已选择的五片。

## 库内 20 款

原展示图不覆盖。`assets/nail-kits/catalog-prompts.json` 保存逐款人工核对的原图 SHA-256、尺寸、五个源图提示点、框、是否标记左手及拇指方向。明确 Left/L 的选左手，未标记的选完整第一排五片；四款纯色的拇指在右端，导出时反向映射。其他款式按核对过的标准排列映射到拇指、食指、中指、无名指、小指。

使用 MobileSAM 从原图分割，生成每款目录：

- `THUMB.png` ～ `LITTLE.png`：甲面透明裁片，保持源图采样尺寸与 RGB。
- 对应 `*-context.jpg`：含饰品、甲片边缘和周围区域的原图裁切。细小立体饰品与甲面可能不是同一连通体，所以不把它们强行当作甲面；原始素材与上下文始终保留，后续贴合/饰品分层可继续使用。
- `manifest.json`：五片对应、源图框、质心、主轴、面积、模型分数和选排依据。
- `reference.png`：仅这五片的统一朝向参考图，使用同一缩放因子，保留彼此相对大小，不含另一排或商品文字。

甲面分割会填充被白色花纹/反光误判的内部孔洞，清理细小支架连接；重叠像素按各片提示点的距离分配，确保同一源图像素不能属于两片。此甲面蒙版不是完整饰品的精确分层结果。

重建脚本为 `scripts/prepare_catalog_nails.py`，依赖 Python 的 onnxruntime 1.20.0、numpy、Pillow；使用固定模型和提示元数据，不调用付费服务。构建脚本不在普通 Gradle 构建时运行。

## 用户相册上传美甲图

1. 在后台按 EXIF 读取、限长至 2048；bundled ML Kit 中文/拉丁文字识别左右标记，MobileSAM 网格提案提取候选物体，再通过几何分组找出完整五片排组。
2. Left/左手/左优先，成对 L/R 可以作为左右手标记，单独尺寸 L 不作为 Left。标记通过空间距离绑定排组；右手在上、左手在下同样能选左手。
3. 没有标记时选完整第一排；OCR 失败、只识别到 Right、左右标记冲突或位置不确定时，要求确认排组，不能冒充已确认左手。
4. 拇指/小指以端点宽度辅助定位，中间三片保持原有顺序，不能简单按宽度排序。端点接近时提示不确定。预览中可以调整五片的指头对应，交换不会复制或遗漏甲片。
5. 没有完整可信排组时，可按拇指到小指顺序点选同一排的五片，再分割并确认。有标记的需选左手，无标记可任选一排。部分分割失败、重复点选或大面积背景不会放行。
6. 确认后保存到应用私有缓存，再进入原有的手部照片选择。新参考素材只有五片；不在这一步处理手部贴合。缓存若被系统清理，要求重新准备，不退回整张十片图。

自定义缓存目录保存无损 `source.png`、五片 PNG、原图上下文、源图坐标轮廓、主轴、来源哈希与五片参考图。主轴朝上只是素材规范化假设，不是甲根/甲尖的可靠解剖判断；实际贴合需在后续任务另做。

## 验证与限制

测试包括标记左手在第二排、成对 L/R、尺寸 L、标记冲突、OCR 失败、倾斜两排、不足五片、双向拇指、中间三片顺序、透明像素与原颜色、五片实例不重用像素、缓存元数据与异常输入。逐一检查 20 款/100 片内置素材的原图哈希、对应顺序、提示点、透明蒙版、像素颜色与参考图。

真实 ONNX 模型测试包含两类展示卡的五片分割、手动五点生产服务和空白图拒绝；UI 测试覆盖选排、改对应、点选、确认保存、失败返回；流程测试验证确认后才进入手部上传，并且只有五片参考图进入原有生成器。

ML Kit 的 Android 原生文字识别无法在 Windows Robolectric 中直接运行；其返回文字与坐标后的判定规则通过单元测试，真实手机 OCR、运行时延迟和各种自选图片仍待实机验收。自动物体提案不是专门训练的穿戴甲检测器，复杂排版可能需五点确认。未宣称能仅凭大小辨别任何乱序甲片，也未实现精确饰品分层。

模型来源和哈希见 `assets/models/NOTICE.MobileSAM.txt`；新增 OCR 使用打包模型，无需用户新建账号或提供 API Key。本次不运行全量测试或打包 APK。
